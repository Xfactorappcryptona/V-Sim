How V-Sim could work for real

A website alone cannot move an eSIM or phone number. This prototype only simulates the experience. A real product would need:

1. Mobile network partnerships

Only the carrier can authorise a number and eSIM profile moving to a new device. V-Sim would need commercial and technical agreements with each operator, and would act as an orchestrator, never the authority.

2. eSIM provisioning (GSMA SM-DP+)

  • Carrier or its SM-DP+ server issues a new eSIM profile for the target device’s EID.
  • Profile download and activation via the phone’s Local Profile Assistant (LPA).
  • Old profile is deactivated only after the new one is confirmed.

3. Device compatibility

Target devices must support eSIM and expose a supported provisioning path. A companion app or OS-level integration (Apple, Google, Samsung) would be needed to read the EID and complete activation.

4. Backend infrastructure

  • Short-lived, single-use PIN service with rate limiting and expiry.
  • Identity and fraud checks (SIM-swap fraud is a major risk).
  • Carrier API gateway, audit logs, retry and rollback handling.
  • Privacy and regulatory compliance (e.g. UK GDPR, Ofcom rules on switching and porting).

5. Security

PIN alone would not be enough. Real flows would add carrier-side authentication, device attestation and out-of-band user confirmation.
